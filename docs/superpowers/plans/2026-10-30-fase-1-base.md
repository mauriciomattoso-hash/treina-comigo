# Treina Comigo — Fase 1 (Base) Implementation Plan

**Goal:** O aluno se cadastra escolhendo o plano e respondendo a anamnese; ela aprova no painel; o plano libera os módulos; ela controla cobranças e edita a biblioteca de exercícios.

**Architecture:** Site estático (HTML + JS em módulos, sem build) publicado por FTP no Hostgator a cada push, como o protocolo. Banco, login e regras de acesso no Supabase da organização dela; toda a separação entre alunos fica nas políticas RLS. Regras de negócio puras ficam em `js/regras.js` e são testadas com `node --test`; o banco é testado com scripts SQL que simulam aluno e admin.

**Tech Stack:** HTML/CSS/JS (ES modules), `@supabase/supabase-js@2` via cdn.jsdelivr.net, Postgres 17 (Supabase, sa-east-1), Node 20 (`node --test`) para os testes, GitHub Actions + SamKirkland/FTP-Deploy-Action@v4.3.5.

**Spec:** doc "Treina Comigo — Desenho do sistema" (https://claude.ai/artifact/Dbeoaw8qd3NXBSZowfEkQ1), seções Como funciona, Dados e infraestrutura e Fases de entrega (fase 1).

## Global Constraints

- Planos e módulos: Treina Comigo = musculação + corrida; Força Comigo = só musculação; Corre Comigo = só corrida.
- Situações do aluno: `pendente` → `ativo` | `recusado`; `ativo` ↔ `pausado`.
- Um aluno nunca lê nem altera dados de outro aluno; isso é garantido no banco (RLS), não só na tela.
- O cadastro sempre nasce `pendente` e nunca como admin, mesmo que o navegador mande outra coisa.
- Login por e-mail e senha, sem confirmação por e-mail.
- Projeto Supabase novo na organização `nhaycsaqgnkngkyamhjx`, região `sa-east-1`, nome `treina-comigo`.
- Pasta provisória: beag.com.br/treinacomigo; repositório `treina-comigo`.
- Biblioteca inicial = os 188 exercícios de `EX_LIB` do protocolo, com instrução e pontos de atenção preenchidos.
- Todo texto de tela em português do Brasil; nome exibido "Treina Comigo".
- Scripts e estilos externos só de cdn.jsdelivr.net e Google Fonts.

## Review Focus

1. **Metadados forjados no cadastro** (aluno manda `status: 'ativo'` ou `is_admin: true` no signUp): continua `pendente` e não-admin → teste `t_signup_forca_pendente` na Task 2.
2. **Plano inexistente ou vazio no cadastro**: o cadastro é recusado com mensagem clara, sem criar perfil órfão → `t_signup_plano_invalido` na Task 2 e `validarCadastro` sem plano na Task 3.
3. **Aluno pendente ou recusado faz login**: vê a tela "aguardando aprovação"/"cadastro não aprovado", nunca o app → `telaDoAluno` na Task 3.
4. **Aluno tenta ler a anamnese ou a cobrança de outro aluno** pela API direto: zero linhas → `t_rls_isolamento` na Task 2.
5. **Cobrança vencendo hoje** e cobrança paga depois do vencimento: hoje = `aberta`, paga = `paga` (nunca `atrasada`) → `statusCobranca` na Task 3.
